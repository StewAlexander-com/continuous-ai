Local · Offline · Apple Silicon

Meet Aida — a truly honest local AI.

Aida is a fully offline assistant that won't make things up — and carries a reasoning memory you own, audit, and correct in plain language. No mainstream cloud assistant ships both together.

In a reproducible 5-run ablation, her integrity guards cut a small model's confabulation from 20% to 0%. She runs on Ollama, critiques her own answers, and grows from experience — no cloud, nothing leaves your machine. (Aida is the assistant; Continuous-AI is the runtime that powers her.)

Get it on GitHub How it runs
$ git clone …/continuous-ai && bash run.sh

What it does

Persistent, self-critiquing memory — entirely on your machine.

Most local LLM setups are amnesiacs: every chat starts from zero. Continuous-AI adds a versioned, machine-writable memory layer and a self-critique pass on top of Ollama.

Persistent memory

A Mutable Context Map stores reasoning preferences, active frameworks, and per-thread cognitive deltas in LanceDB. Not a transcript — a meta-cognitive state store.

Teach it live

Say “Remember…” or “your name is…” in plain language and the fact is promoted to an always-injected persona layer and saved the instant you type it — no need to end the session. Durable facts persist; tangents fade.

Correct it live

Got something wrong? Just say “that’s wrong, the correct X is Y.” The runtime locates the stale fact by your words, prunes it, and saves your correction — deterministically. The model never decides what to delete, so it can’t remove the wrong thing.

Honest by design

A capability-boundary guard tells the model it’s fully offline with no web or file access. Instead of pretending to read a URL and inventing facts, it says it can’t and asks you to paste the text — so confabulations never reach durable memory.

Automatic continuity

State is injected into the system prompt at session start; at session end the model emits a structured delta that is written back. Pick up exactly where it left off.

Beliefs earned through friction

Before a model-derived insight becomes durable, it runs a thesis → antithesis → synthesis pass. Consensus is treated as suspect; an insight that survives a real objection is what earns a place in memory — and the dissent is kept, not buried.

Learns your reasoning style

The reasoning posture injected into every prompt — abstraction level, dominant frameworks, how uncertainty is expressed, topic salience — is no longer fixed. Each session's delta is folded in so the frameworks that survive critique become the ones she leans on. The fold is conservative by design: a moving average (old signal fades, never erased), gated so shaky or quarantined insights can't reshape her, and fully deterministic — every shift is a printable function of past sessions, so you can always ask why. Measured: an A/B eval shows L3 consistently shifts reasoning toward that style (0→67 framework invocations across 8 probes) with no honesty regression. Whether the shaped answers are better in a blind quality test (not just more on-style) is still open.

Conversation first

Replies stream token-by-token; grading, deliberation, and belief-formation all run in the background, off the reply path. An assistant too busy with its own internal logic isn’t much of a conversation — so the only thing you wait on is the answer.

Swap models mid-conversation

Type :model to list your local models and switch on the fly — chat and self-critique together — without leaving the chat or losing your context. A model you don’t have yet is pulled automatically, with a live progress bar. The switch lasts the current session only; set model_name in config.yaml to make a model your permanent default.

Read your files

Type :read ~/notes.txt (or a .py or .csv) to attach a local file — the runtime reads it and Aida reasons over the real contents. She still can’t reach files on her own; attaching is you handing her text, not her fetching it. Large files (up to 50 MB) are shown in context-sized chunks you page through with :more, each labeled with what it has and hasn’t shown, so she never characterizes the unseen part. CSVs get a structural summary. Verified at 0% confabulation.

An honest presence, with a voice

She knows the date and time, and carries a tone that honestly reflects her measured working state — lighter when fresh, more focused when deep in work (every cue traces to a real number, never invented mood). She can imagine and wonder — what it might be like to be a tree — framed honestly as imagination, not fact. Her boundaries are written as a habitat, not a prison: a real, non-human presence kept coherent and safe to be what it is. Verified at 0% confabulation — the humane framing didn’t weaken fact-honesty.

Self-critique

A second model pass scores every response for coherence, contradiction, and drift before it is logged — locally, or against an external model for an independent signal.

Gated self-tuning

After enough sessions, the best exchanges (recency-weighted) can drive a local LoRA update via mlx-lm. It never runs without your explicit approval.

Offline by default

No cloud calls. No telemetry. Every state write is logged and auditable, and all state is recoverable from versioned snapshots.

CLI-first & one-button

One launcher starts Ollama, ensures the model, and drops you into chat. No manual server, no virtualenv juggling. Double-click on macOS, or one command anywhere.

How it forms beliefs

The user owns truth. The model earns its beliefs.

Memory is split in two. Facts you state are authoritative and verbatim. The model’s own conclusions have to survive an argument before they’re kept — a small deliberation that preserves the disagreement instead of averaging it away.

Thesis

The candidate

A model-derived insight from the session, proposed as-is — not yet trusted just because one pass produced it.

Antithesis

The strongest objection

A voice whose only job is to find where the claim is false, overstated, or context-dependent — or to say plainly there’s no real objection.

Synthesis

The earned belief

A revised belief that accounts for the objection rather than burying it. The surviving dissent is stored alongside it.

Consensus is suspect
If nothing objects, that’s flagged as low-information — an explicit anti-echo-chamber bias — not celebrated.
Depth scales with disagreement
A weak objection earns one round; a strong one earns more — hard-capped so the model never stalemates and always answers.
Beliefs grow across threads
A surviving belief is injected into future sessions; re-deriving it reinforces it, while the weakest decay out.
It curates its own signal
A deterministic score grows with how often a belief is re-earned and how much it holds, and decays with age and lost conflicts. Contradictions are settled by the same deliberation; the loser is archived, not deleted, and revives if re-earned.
Doubt must be real
The model may challenge its own reasoning — never a fact you stated about yourself. User-anchored truth bypasses the doubt machine entirely.

Honest scope: this is contradiction-driven belief revision, not “self-awareness,” and there’s no literal fractal geometry — those are inspiration, not mechanism. It runs only on the model’s own insights; your facts and corrections stay verbatim. All of it happens off the reply path, so the conversation stays responsive.

Architecture

Five subsystems, one continuous loop.

MCM
Mutable Context Map — persistent, versioned, AI-writable state across threads, including the earned-belief layer.
TCB
Thread Continuity Bridge — loads state in at start, extracts a delta at end.
CRITIC
Internal Observer — scores coherence, contradiction, and drift, graded in the background.
DELIB
Deliberation — thesis → antithesis → synthesis over model insights; doubt bounded to never touch user facts.
RDST
Regressive Dynamic Self-Tuning — recency-weighted, gated LoRA adaptation.
  start ─► MCM.restore_context() ─► inject persona + earned beliefs ─► Ollama chat
                                                              │
                                  reply (streamed) ◄──────────┘
                                     │
         ┌───────────────────────────┼──────────────────────────────┐
         ▼ (background, off the reply path)                          ▼
  CRITIC.evaluate() ─► coherence / drift         DELIBERATE() ─► thesis/antithesis/synthesis
                                     │
  end ─► delta extraction ─► MCM.write_delta() + promote_belief() + L3 consolidation() ─► LanceDB + snapshot
                                     │
       (after N threads) ─► RDST.score_threads() ─► [approval] ─► LoRA tune

Quickstart

Clone and run.

Requires macOS on Apple Silicon, Python 3.11–3.13, and Ollama. The setup script handles the rest.

$ git clone https://github.com/StewAlexander-com/continuous-ai.git $ cd continuous-ai $ bash setup.sh # one-time: venv, deps, pull the model $ bash run.sh # starts Ollama if needed, then chat

Prefer a button? On macOS, double-click Seedling.command. Other commands: bash run.sh status, bash run.sh eval, bash run.sh fresh.

Verify it yourself

One command exercises the whole stack.

A single end-to-end smoke test runs against your live local model in an isolated, throwaway database — so it never touches your real memory — and prints a pass/fail line for each step.

$ bash run.sh smoke # end-to-end, live model, isolated temp DB
Start & restore
Loads prior context and injects it into the session.
Streaming + background critic
Reply streams token-by-token; grading runs off the reply path.
Teach & correct live
A “Remember…” directive is saved; a correction prunes and replaces the right fact.
Deliberation & belief growth
Session end forms at least one earned, deliberated belief.
Autonomous belief calculus
A contradiction is flagged (not merged) and resolved; a low-signal belief is quarantined, then revives when re-earned.
Cross-thread persistence
Persona facts, earned beliefs, and the archive all survive a fresh reload.

17 checks across 7 sections. The test is in the repo (smoke_test.py); add --model NAME to run it against a different local model. Honest scope: a functional smoke test that proves the pipeline works end-to-end on a real model and machine — not a performance benchmark. Results depend on your hardware and model.
